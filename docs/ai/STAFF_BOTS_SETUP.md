# Боты сотрудников: запуск Telegram и MAX

Код ботов и галереи находится в Django. Telegram Mini App находится во фронтенде Quasar/Vue по пути `/master-app`. Сценарий рассчитан на сотрудников с профилем мастера; для других ролей доступ не открыт. До получения токенов и регистрации вебхуков боты не принимают события.

## Что нужно сделать в мессенджерах

1. **Telegram.** В официальном [@BotFather](https://core.telegram.org/bots/features#botfather) выполнить `/newbot`, задать имя и username бота, сохранить выданный токен в секретах сервера. Username должен оканчиваться на `bot`. Не добавлять токен в Git или переписку с мастерами.
2. **MAX.** Создать и верифицировать профиль компании на [платформе MAX для партнёров](https://dev.max.ru/docs/chatbots/bots-create/create), создать чат-бота и дождаться модерации. После публикации получить токен в настройках бота. Для MAX нужен действительный HTTPS-сертификат на порту 443; [документация вебхука](https://dev.max.ru/docs-api/methods/POST/subscriptions) также описывает проверку секретного заголовка.

## Настройка сервера

После развёртывания миграций `masters.0020` и `masters.0021` задать переменные окружения Django:

```text
TELEGRAM_BOT_TOKEN=<токен от BotFather>
TELEGRAM_WEBHOOK_SECRET=<случайная строка из букв, цифр, _ и ->
TELEGRAM_PROXY_URL=<адрес SOCKS5-прокси из настроек сервера>
TELEGRAM_MINI_APP_URL=<публичный HTTPS-адрес мини-приложения>
MAX_BOT_TOKEN=<токен MAX после модерации>
MAX_WEBHOOK_SECRET=<случайная строка из букв, цифр, _ и ->
```

Секреты вебхуков должны быть отдельными от токенов ботов. `TELEGRAM_MINI_APP_URL` по умолчанию равен `SITE_URL/master-app` и должен быть публичным HTTPS-адресом. Можно подключать платформы по одной: без токена и секрета соответствующий endpoint отвечает `503`. Публичные HTTPS-адреса на текущей схеме доменов:

```text
https://api.studio.scissors.group/webhooks/staff/telegram/
https://api.studio.scissors.group/webhooks/staff/max/
```

Telegram webhook регистрируется кнопкой «Зарегистрировать webhook в Telegram» на странице «Интеграции → Telegram webhook» в админке `https://admin.studio.scissors.group/`. Страница доступна только суперпользователям. Запрос [setWebhook](https://core.telegram.org/bots/api#setwebhook) отправляется с сервера через `TELEGRAM_PROXY_URL` с `secret_token`, равным `TELEGRAM_WEBHOOK_SECRET`, и `allowed_updates=["message"]`. Все исходящие вызовы Telegram API, включая отправку сообщений и загрузку фото, требуют этот SOCKS5-прокси. При отдельном адресе webhook задайте `TELEGRAM_WEBHOOK_URL`. Зарегистрировать MAX webhook через [POST /subscriptions](https://dev.max.ru/docs-api/methods/POST/subscriptions) на `https://platform-api2.max.ru`, передав URL выше, `update_types=["message_created"]`, `secret` равным `MAX_WEBHOOK_SECRET` и токен в заголовке `Authorization`. Для MAX токен нельзя передавать в query string.

## Подключение мастера и команды

В карточке мастера в админке открыть «Мессенджеры» → «Создать код подключения». Код показывается один раз, действует 15 минут и предназначен только этому мастеру. Мастер открывает личный чат с Telegram-ботом, отправляет `/start`, нажимает «Подключить профиль» и вводит код ответом на сообщение. Команда `/link КОД` также работает. После привязки бот показывает кнопку «Открыть кабинет мастера». Для Telegram и MAX нужны два отдельных кода. Один аккаунт каждой платформы может быть связан только с одним мастером; в админке подключение можно отключить.

Мини-приложение позволяет редактировать описание, фото профиля, общую галерею и работы по назначенным услугам. Django проверяет подписанное Telegram `initData` при каждом запросе и находит уже привязанный Telegram ID. Открытие `/master-app` напрямую в браузере не даёт доступа к данным.

Команды после подключения:

- `/profile` — показать имя и описание;
- `/bio` — затем отправить новый текст описания; `/bio Новый текст` тоже работает;
- `/photo` — затем отправить новое фото профиля;
- `/gallery` — затем отправить фото в общую галерею страницы;
- `/services` — показать назначенные услуги и их ID;
- `/work ID` — затем отправить фото работы по услуге с этим ID;
- `/cancel` — отменить ожидаемое действие.

Фотографии принимаются только в личных чатах. Для работы по услуге сначала должна существовать связь мастер–услуга. Поддерживаются JPEG, PNG, WEBP и GIF до 10 МБ. Описание сохраняется как безопасный текст. Изменения `bio` и `photo` в текущей синхронизации YCLIENTS не перезаписываются.

## Проверка после подключения

1. Создать тестовый код в админке, подключить тестового мастера и проверить `/profile`.
2. Отправить `/bio`, `/photo`, `/gallery`, `/work ID`; проверить карточку мастера, общую и сервисную галереи на сайте.
3. Проверить, что чужой код и чужой ID услуги не позволяют изменить профиль.
4. При ошибках доставки проверить состояние Telegram через `getWebhookInfo` и подписки MAX через `GET /subscriptions`.

Для MAX фотографии загружаются по временной HTTPS-ссылке из `image.payload.url`, описанной в [схеме события MAX](https://dev.max.ru/docs-api/methods/GET/updates/). Реальный бот и токен пока не предоставлены, поэтому внешний обмен с MAX и Telegram нужно проверить после регистрации ботов.

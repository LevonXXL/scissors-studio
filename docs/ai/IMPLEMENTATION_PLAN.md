## Следующий рабочий поток: Excel ↔ YCLIENTS ↔ БД

Владелец подготовил дамп `scissors_db.07.11.2026.sql` и восстановил его в локальной БД. В админке услуг добавлена «Сверка YCLIENTS»: она получает текущие услуги и мастеров в предпросмотр, показывает расхождения как импорт Excel, предлагает соответствия из проверенного манифеста, по названию и через поиск услуг Excel без ID YCLIENTS. Поиск начинается после трёх символов и использует единый JSON по салону на странице. Статусы «Готова к применению», «Сохранена» и «Требует решения» разделены; галочка слева относится только к групповому применению, а кнопка справа сохраняет конкретную строку. Фильтры «Только проблемные» и «Без назначений» работают по текущим статусам и фактическим связям мастер–услуга; после успешного сохранения строка исчезает из второго фильтра, если недостающих назначений не осталось. Источник истины для услуг и цен — Excel: новые услуги из YCLIENTS не создаются, цены не переносятся. При однозначной свободной паре `Service.yclients_service_id` заполняется; другие подтверждённые пары хранятся в `YClientsServiceMatch` по салону, назначения — в `ServiceStaffPrice`. Новая миграция `services.0011` применена к локальной БД.

Read-only сверка 7 ноября 2026 года: 417 активных строк YCLIENTS для двух салонов, 242 с предложением по манифесту, 175 требуют ручного выбора, неизвестных ID мастеров в этих строках нет. Это число предложений, а не подтверждённых соответствий; назначений в БД до ручного сохранения строк не было. Для 15 разных названий из этих расхождений добавлены отдельные подсказки ИИ (`services/ai_service_suggestions.json`); с учётом двух салонов они могут появиться в 16 строках. Подсказки не выбираются автоматически и не уменьшают число строк, требующих решения администратора.

1. **Разобрать 175 строк без готового соответствия.** ИИ нужен прежде всего для сопоставления смысла названий услуг из YCLIENTS, Excel и БД, например «Мужская стрижка» и «Мужская стрижка | Man Cut». ID мастеров в текущей выгрузке уже сопоставлены по `MasterSalon`; здесь семантическая помощь не нужна. Проверить длину волос, состав услуги и доступность по салону; сохранить ручное решение по каждой строке в админке. Текстовая похожесть и подсказки ИИ — только варианты для проверки, не доказательство.
2. **Подтвердить предложенные пары.** Проверить предложенные соответствия, включая случаи, где одной услуге YCLIENTS отвечают несколько услуг каталога. Однозначные проверенные строки можно применить группой; для расхождений выбрать услугу Excel и сохранить строку отдельно. Если услуги нет в Excel, оставить строку без назначения. Не удалять старые назначения автоматически. Мастер может затем самостоятельно добавлять и убирать свои назначения и менять индивидуальную длительность на странице «Мои услуги» в своём профиле админки.
3. **Установить актуальные уровни мастеров.** Собрать признаки из прайса и подтверждённых назначений, но сохранять `Master.price_level` только после проверки человеком: это ручное поле, которое синхронизация YCLIENTS не меняет.
4. **Сверить итог.** Сравнить количества подтверждённых соответствий и назначений по салонам, проверить ошибки `ServiceStaffPrice.clean()` и длительности мастеров. Не изменять цены и контент `Service.page.content` в рамках этого процесса.

## Отложено по решению владельца

- **Заявка «Хочу в команду».** Форма найма сейчас не нужна. Видимая кнопка на `/vacancy` скрыта; создание формы и обработчика не планировать без нового запроса.

- **Единый прайс, столбец W.** Не импортировать развёрнутое описание в `Service.page.content` и не перезаписывать существующий контент. Текущая синхронизация импорта не меняет этот запрет.
- **Остальные внешние сервисы.** Для Manticore, Celery/Redis и Web Push отдельной задачи на проверку среды сейчас нет. Работа с YCLIENTS и переход Rewio на ключ заказчика описаны выше.

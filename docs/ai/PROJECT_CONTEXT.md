# Контекст проекта Scissors Studio

Срез репозитория: 7 ноября 2026 года, ветка `main`, коммит `871fe3b` (`calendar`). Этот документ описывает код в рабочем дереве, а не состояние развёрнутого сервиса.

## Структура и архитектура

Репозиторий состоит из двух приложений. `scissors-backend/` — Django 5.2 + Django REST Framework; `scissors-frontend/` — Vue 3 + TypeScript на Quasar 2, с SSR и PWA. Корневой `Makefile` и Makefile каждого приложения содержат в том числе команды удалённого развёртывания.

### Backend

- `scissors_studio/settings.py`, `urls.py`, `celery.py` — конфигурация, маршрутизация и фоновые задачи. Публичное API собрано из URL-модулей приложений под `/api/v1/`; схема доступна через `drf-spectacular` под `/api/schema/`. Django Admin находится в корневом маршруте.
- `pages` — дерево CMS-страниц (`django-mptt`), содержимое и изображения. `PageViewSet` выдаёт опубликованные страницы и поиск по `url_path`.
- `salons`, `masters`, `services` — каталог салонов, мастеров, услуг и цен. Связь мастера с салоном вынесена в `MasterSalon`; цены и доступность услуг моделируются отдельными сущностями.
- `booking` — локальные записи и заявки, API вариантов услуг и мастеров, список записей клиента, админский календарь, напоминания и клиент YCLIENTS.
- `client_auth` — подтверждение телефона/почты, вход и JWT; `communications` — обратная связь и Web Push; `reviews` — отзывы и импорт Rewio.
- `sync` — импорт и согласование данных YCLIENTS; `search` — документы, индексирование и API поиска Manticore; `core_utils` — общие вспомогательные функции.

Для моделей используются миграции по приложениям; типовой путь данных — модель → сериализатор/представление DRF → API. Для внешних источников есть отдельные клиенты, management-команды и тесты. По умолчанию БД локальной разработки — SQLite, при `DATABASE_URL` используется указанная БД (в документации описан PostgreSQL). Celery/Redis обслуживают напоминания, а Manticore — поиск. Медиа и превью используют `django-filer`, `easy-thumbnails` и отдельный endpoint `/thumbnail/`.

Ключевые серверные зависимости закреплены в `requirements.txt`: Django 5.2.17, DRF 3.17.1, Simple JWT, drf-spectacular, Celery, Redis, psycopg, django-mptt, django-filer, django-ckeditor-5, django-unfold, requests и pywebpush. Настройки окружения и внешних сервисов заданы в `settings.py`; секреты не являются частью этого документа.

### Frontend

- `src/router/routes.ts` задаёт явные страницы и последний catch-all для `PageView.vue`. Все основные маршруты вложены в `MainLayout.vue`.
- `src/pages/` содержит страницы; `src/components/` — повторно используемые блоки; `src/data/` — локальный контент и константы.
- `src/api/client.ts`, `endpoints.ts`, `types.ts` отделяют Axios и типизированные вызовы от компонентов. `src/stores/` содержит Pinia-сторы для загрузки и хранения данных. `src/config/urls.ts` и `src/utils/` формируют публичные адреса и ссылки.
- Quasar `preFetch` и `onServerPrefetch` загружают данные для SSR; состояние Pinia передаётся клиенту. `src-ssr/` содержит Express-сервер и middleware, `src-pwa/` — manifest и service worker. `public/` содержит статические файлы.

На главной странице часть текста и изображений берётся из `src/data/home.ts`, а страницы/категории/отзывы загружаются через API. Команда, салоны, каталог услуг, поиск, профиль клиента и заявки имеют код интеграции с backend. `PageView.vue` отображает CMS-страницы по пути, включая каталог `/uslugi`. Следовательно, описание «всё статично, API пока не подключён» в `scissors-frontend/README.md` уже устарело.

Основные frontend-зависимости: Vue 3, Vue Router 5, Pinia 4, Quasar 2, Axios; сборка — `@quasar/app-vite`, проверка типов — `vue-tsc`, форматирование — Prettier. Версии и ограничения Node см. в `scissors-frontend/package.json`. SSR-пакет отдельно объявляет Express, Helmet и compression; PWA-пакет — Workbox.

## Реализовано и открытые участки

Подтверждено кодом: API каталога/CMS/отзывов/поиска, клиентская маршрутизация и SSR, авторизация и заявки на запись, админский календарь, синхронизация YCLIENTS, команды индексации Manticore. Наличие кода само по себе не подтверждает работоспособность внешних сервисов в production.

- `/booking` сейчас ведёт на внешний YCLIENTS; параллельно существуют `booking-options/` и `booking-requests/` для локальной заявки. Полный клиентский поток выбора слота и создания записи непосредственно через Booking API YCLIENTS не показан в маршрутах и `BookingPage.vue`. В `booking/services.py` явно указана необходимость сверить реальные пути и ответы YCLIENTS перед использованием. По решению владельца развитие бронирования пока приостановлено: параллельно разрабатывается Pigeon CRM, а действующие ссылки на запись должны вести в YCLIENTS.
- Набор вакансий через сайт сейчас не нужен; кнопка «Хочу в команду» на `VacancyPage.vue` скрыта, неиспользуемый обработчик в `TeamPage.vue` удалён. Статический `src/data/masters.ts` содержит непроверенные ссылки/фото, хотя текущий `TeamPage.vue` получает мастеров из API; использование этих данных следует проверять по месту, прежде чем править.
- `TODO.md` откладывает импорт столбца W единого прайса в `Service.page.content` и прямо запрещает пока перезаписывать существующий контент. Владелец подтвердил, что этот участок пока не трогаем, несмотря на текущую работу по синхронизации импорта.
- Ближайшая работа с YCLIENTS — получение данных, сопоставление названий услуг из Excel, YCLIENTS и БД, восстановление связок мастер–услуга и максимально полное установление актуальных уровней мастеров. Excel — источник истины для услуг и цен: отсутствующие в нём услуги из YCLIENTS не создаются, цены не импортируются. Помощь ИИ относится к названиям услуг и их смыслу, а не к поиску ID мастеров: последние уже связываются через `MasterSalon.yclients_staff_id`. Различающиеся названия, например «Мужская стрижка» и «Мужская стрижка | Man Cut», требуют нормализации или ручного подтверждения. В коде уже есть `services/unified_excel_import.py` с поиском кандидатов, `reconcile_service_staff` с проверяемым манифестом и предпросмотром, а также админский экран `ServiceAdmin.review_yclients` с групповой и построчной сверкой. Он предлагает услуги Excel без `yclients_service_id`, заполняет этот ID при однозначной свободной паре и переносит назначения; другие подтверждённые пары сохраняются в `YClientsServiceMatch` по салону. Мастер может редактировать собственные назначения и длительность через страницу «Мои услуги» своего профиля админки. Файл `services/ai_service_suggestions.json` хранит подсказки, вручную сопоставленные по смыслу названий из выгрузки; они показываются без автоматической отметки. `Master.price_level` помечен как устанавливаемый вручную; `sync/sync_service.py` его не перезаписывает. Актуальный дамп `scissors_db.07.11.2026.sql` загружен владельцем в локальную PostgreSQL.
- В связке `ServiceStaffPrice` уже есть `duration_seconds` для индивидуальной длительности мастера. Вычисляемая `effective_duration_seconds` берёт его при заданном значении, иначе `Service.duration_seconds`; API каталога отдаёт итоговую длительность для каждого мастера. Новая миграция для этого правила не требуется.
- В ответе YCLIENTS `service_categories/{company_id}` у категории есть массив `staff` с ID мастеров, а у каждой услуги `services/{company_id}` есть собственный массив `staff`. Проверка 8 ноября 2026 года для Михаила Стеця показала, что принадлежность категории не означает назначение всех её услуг: в каждом из двух салонов по 12 активных услуг входят в категории мастера, но не содержат его в собственном `staff`. Следовательно, категорию можно использовать как вспомогательный сигнал при сверке, а создавать `ServiceStaffPrice` следует по подтверждённому назначению конкретной услуги или по ручному выбору. В локальной БД у мастера 107 одна такая связь; в общей карточке администратора добавлена ссылка на её просмотр и редактирование.
- `MasterServiceWorkPhoto` хранит отдельные фотографии работ мастера с привязкой к услуге; прежняя общая галерея мастера остаётся в `PagePicture`. Галерея по услугам доступна мастеру и администратору из карточки мастера, а публичное API страницы отдаёт её отдельно для группировки на сайте. Миграция `masters.0020` добавляет таблицу.
- Боты сотрудников используют одноразовый код из карточки мастера для привязки личного чата Telegram или MAX. Команды меняют `Master.bio`, `Master.photo`, общую галерею и `MasterServiceWorkPhoto` для уже назначенных услуг. Вебхуки защищены секретным заголовком и не принимают сообщения из групп. Миграция `masters.0021` добавляет привязки и коды. Токены и секреты ещё не настроены; инструкция по созданию ботов и запуску — `docs/ai/STAFF_BOTS_SETUP.md`.
- Rewio переходит на новый API-ключ, предоставленный заказчиком. Клиент читает `REWIO_API_KEY` из окружения; сам ключ не должен попадать в репозиторий. Связь существующих `rewio_object_id` с новым доступом ещё не проверена.
- `npm run lint` ссылается на отсутствующий `scissors-frontend/eslint.config.js`. В `tests/` есть тесты messenger-ссылок и thumbnail URL, но в `package.json` прописан только скрипт для первого.
- Оба README содержат исторические планы и отдельные утверждения, уже расходящиеся с кодом: backend README перечисляет лишь три приложения и говорит об отсутствии booking views; frontend README описывает преимущественно статический этап, отсутствие ассетов и favicon. Проверять текущее состояние нужно по исходникам.

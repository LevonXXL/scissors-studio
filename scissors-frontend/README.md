# Scissors Studio — фронтенд (Quasar + SSR + PWA)

Собран с нуля через `create-quasar` (TypeScript + Pinia), с добавленными
режимами SSR (Express) и PWA.

## Стратегия миграции (два этапа)

1. **Сейчас** — статичная копия текущего сайта на Tilda: реальный контент
   (тексты, цены, карточки мастеров) захардкожен прямо в компонентах, без
   обращений к Django API. Цель — визуальный и структурный паритет с
   существующим сайтом на новом стеке.
2. **Дальше** — постранично вытесняем статику на данные из DRF
   (`/api/v1/pages/`, `/api/v1/salons/`, `/api/v1/masters/` — эндпоинты и
   типы уже готовы в `src/api/`, `src/stores/pages-store.ts` и
   `src/pages/PageView.vue`, просто пока не подключены к большинству страниц).

## Установка

```bash
npm install
npm run dev          # dev-сервер с SSR
quasar build -m ssr  # прод-сборка SSR
quasar build -m pwa  # прод-сборка PWA
```

Публичные адреса задаются при сборке: `SITE_URL` (канонический адрес
сайта), `API_ORIGIN` (адрес Django API), `MEDIA_URL` (адрес медиафайлов).
При необходимости можно задать `VITE_SITE_URL`, `VITE_API_BASE_URL` и
`VITE_MEDIA_URL` отдельно для frontend. В разработке используются
`localhost:9100` и `localhost:8000`; в production значения по умолчанию
соответствуют текущим доменам. Для Яндекс.Карт нужен
`VITE_YANDEX_MAPS_API_KEY`. После смены `SITE_URL` пересоберите SSR/PWA;
`/robots.txt` формируется SSR из этого адреса.

## Структура страниц

Все страницы монтируются в `MainLayout.vue` (один общий layout — шапка с
телефонами и навигацией, подвал с адресами салонов и юр. данными). Список
маршрутов — `src/router/routes.ts`.

Что статично сейчас, с реальным контентом из дампа Tilda: `HomePage`,
`AboutPage`, `VacancyPage`, `TeamPage` (образец из ~30 мастеров), `SalonsPage`,
`PriceListPage`, `ServicePage` (один компонент на все 6 категорий услуг,
данные — `src/data/services.ts`), `PolicyPage` (только начало документа,
полный текст — bulk-перенос отдельным шагом).

⚠️ **`VacancyPage.vue` содержит формулировки, ранее отмеченные в контентном
аудите** ("оформление по ТК РФ", "выплата зп в срок") — скопированы
дословно намеренно, для визуального паритета на этом этапе. Решение о
правке текста — отдельная задача, не для этапа вёрстки.

`epilation` и `forman` в `services.ts` — без конкретных позиций (`items: []`):
на исходных страницах не нашлось достаточно текста, чтобы не выдумывать
контент. Показывается плашка со ссылкой на `/price-list` вместо пустого блока.

## Два реальных бага, найденных и исправленных при проверке

Оба не были очевидны на глаз — вскрылись только при реальном запуске
собранного SSR-сервера и прогоне всех маршрутов через `curl`, а не при
чтении кода:

1. **Неверный путь виртуального импорта** в `src/boot/axios.ts` —
   `#q-app/wrappers` вместо `#q-app`. Ломало сборку клиента полностью
   (`Build failed`). Нашёл, сверившись с `defineBoot` в шаблонах самого
   `@quasar/app-vite`.
2. **Не зарегистрирован Meta-плагин Quasar** (`quasar.config.ts` →
   `framework.plugins`) — из-за этого `useMeta()` крашил SSR-рендер вообще
   любой страницы с `TypeError: Cannot read properties of undefined
   (reading 'push')`. Без этого фикса **вообще ни одна страница не
   рендерилась на сервере** — все отдавали 500. Добавлено `plugins: ['Meta']`.

Дополнительно: `SalonsPage`/удалённый `MastersPage` изначально дёргали DRF
API эагерли без обработки ошибок — если бэкенд недоступен, это роняло
**весь Node-процесс SSR целиком** (не только страницу), из-за необработанного
unhandled promise rejection. Исправлено переводом этих страниц на статику
(этап 1) и добавлением try/catch в `pages-store.ts` для будущего этапа 2 —
ошибка API теперь логируется и не убивает сервер.

## Недостающие ассеты — see `tilda_assets_urls.txt` / `download_tilda_assets.sh`

Из песочницы нет доступа к `static.tildacdn.com` (не в белом списке egress) —
логотип, favicon и ~180 фотографий с сайта нужно скачать самостоятельно.
Оба файла лежат рядом с этим README. Запуск:

```bash
bash download_tilda_assets.sh
```

Скачает всё в `./tilda_assets/<tild-хэш>/<имя файла>`. Приоритет — два самых
важных файла (логотип и favicon), они не пронумерованы и легко узнаваемы по
имени: `Rectangle_1.png` (логотип) и `Frame_1000005578.ico` (favicon).
Остальные ~180 файлов — в основном фото мастеров/салонов/услуг с
неинформативными именами (`1.png`, `2.png`...) — быстрее сверить визуально
после скачивания, чем пытаться угадать по имени файла.

После скачивания: логотип — в `src/assets/`, подключить в
`MainLayout.vue` вместо текстовой заглушки "SCISSORS STUDIO"; favicon — в
`public/favicon.ico`; фото мастеров — по одному в `src/assets/masters/` и
подключить в `TeamPage.vue`.

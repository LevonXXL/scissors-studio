# Внутренняя статистика Scissors

Сбор использует существующий PostgreSQL, Django и Angie. Никаких внешних сервисов и нового хранилища. Код лежит в приложении `scissors-backend/analytics`.

## Источники и сроки

- Браузер вызывает `navigator.sendBeacon('/analytics/beacon/', {path, ts})` при открытии страницы и переходе. Для этого не создаются cookie, `localStorage` или `sessionStorage`; согласие на Яндекс Метрику на этот вызов не влияет. Эндпоинт принимает только известный публичный путь и время в пределах пяти минут, не читает и не записывает идентификатор посетителя. Совпадающие путь и миллисекунда принимаются один раз. Angie ограничивает запросы до 30 в минуту на IP, Django ограничивает совокупный объём до 50 000 просмотров пути за час.
- При приёме события Django сохраняет только путь, время события и время получения, затем увеличивает часовой счётчик просмотров. Сырые события удаляются через 90 дней.
- Ежечасная команда читает отдельный лог Angie для `/api/`, нормализует URI к шаблону Django-маршрута без параметров и инкрементирует счётчик вызовов и ответов 4xx/5xx. Курсор файла хранит только inode и байтовую позицию; изменения счётчиков и курсора входят в одну транзакцию. После ротации команда дочитывает `.1` до нового файла.
- Для дневных посетителей команда заново читает записи Angie о принятых beacon-запросах за текущий день. Только во время выполнения она группирует IP + User-Agent с дневной солью, производной от `SECRET_KEY` и московской даты. Окно неактивности сессии — 30 минут. Хэш, IP, User-Agent и данные отдельных сессий не попадают в БД. После полуночи ночная команда пересчитывает вчерашний день. Дневные посещенческие значения удаляются после 90 дней, когда исходные записи уже недоступны.
- Часовые счётчики сохраняются для семи последних московских календарных дней и затем сворачиваются в дневные; дневные счётчики не удаляются и доступны минимум два года. Повторные запуски команд не удваивают данные.

**Ограничение:** одинаковые IP и User-Agent в один день будут оценены как один посетитель; это приблизительная метрика. При отсутствии Angie-лога посещенческие значения за день неизвестны и на графике не подменяются нулём. Нули для отсутствующего трафика в базовых счётчиках рисуются явно.

## Подключение на сервере

1. Выпустить код и применить `python manage.py migrate analytics`.
2. Добавить содержимое `angie-http.conf` в контекст `http` (например, `/etc/angie/http.d/00-scissors-analytics.conf`). В HTTPS-блоке API подключить `angie-api-server.inc`, в HTTPS-блоке сайта подключить `angie-frontend-server.inc`. Поскольку текущие серверные конфиги находятся вне репозитория, проверить расположение `include` относительно `location /` и выполнить `angie -t` до reload.
3. Установить `logrotate-angie.conf` как `/etc/logrotate.d/scissors-analytics`. Выделенные `.access`-файлы не попадают под существующий блок Angie для `*.log`; сроки хранения логов других проектов остаются прежними. Команды запускаются от `levon`, который состоит в группе `adm` и может читать логи Angie с правами `0640`.
4. Установить расписание из `crontab-levon.txt` и один раз запустить `aggregate_angie_logs` для проверки прав доступа. Отчёт доступен staff в админке по `/analytics/report/`.

## Текст для политики

> Для оценки посещаемости и работы сайта ведётся внутренняя статистика без cookie и иных идентификаторов в браузере, в том числе для пользователей, отказавшихся от Яндекс Метрики. Сохраняются количество просмотров страниц, вызовов API и ошибок по времени и разделам сайта. События просмотра содержат только путь страницы и время и удаляются через 90 дней. Для оценки числа посетителей и сессий IP-адрес и User-Agent временно обрабатываются в оперативной памяти при анализе журналов веб-сервера; в статистических таблицах они, их хэши и данные отдельных посетителей или сессий не сохраняются. Журналы веб-сервера ротируются и удаляются по истечении 90 дней. Дневные обезличенные счётчики сохраняются минимум два года.

Формулировка намеренно разделяет статистические таблицы и технические журналы Angie: журналы до ротации содержат IP и User-Agent, поэтому утверждение, что они нигде не хранятся, было бы неверным. Перед публикацией сопоставить этот текст с уведомлением РКН и действующей политикой.

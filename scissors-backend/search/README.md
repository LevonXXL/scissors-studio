# Поиск Scissors Studio

Поиск использует **одну** RT-таблицу Manticore `scissors_index`. В неё попадают
опубликованные страницы, реальные активные специалисты, активные салоны,
доступные категории и услуги. Документы имеют поля `title`, `content`,
`search_text` и атрибуты `type`, `url`, `project`, `generation`. `generation`
нужен для удаления документов, которые больше не представлены в публичных
данных PostgreSQL. Русские и английские слова обрабатывает встроенный
`stem_enru`; китайская токенизация здесь не используется.

## Настройка и запуск

Уже работающий экземпляр Manticore можно использовать совместно с
Chinese-Russian: его `universal_index` остаётся отдельной таблицей. В окружении
Django задайте `MANTICORE_HOST` с HTTP-адресом этого экземпляра, например
`http://127.0.0.1:9570`, если он действительно слушает этот порт на том же
сервере. Значение по умолчанию в коде — `http://127.0.0.1:9308`.

Из `scissors-backend/`:

```sh
python manage.py index_manticore --dry-run
python manage.py index_manticore
```

Второй вызов создаёт таблицу **только если её нет**, сверяет схему, обновляет
документы пакетами по 400, удаляет устаревшие документы проекта после успешной
записи всех пакетов и сравнивает итоговое количество с PostgreSQL. `DROP TABLE`
и `TRUNCATE` не используются. При ошибке пакета команда завершается до удаления
старых документов.

После изменения одной записи можно обновить или удалить её из индекса:

```sh
python manage.py index_manticore --type service --id 123
```

Поддерживаемые типы: `page`, `master`, `salon`, `category`, `service`. Если запись
стала непубличной или удалена из PostgreSQL, этот вызов удалит её из Manticore.
Для изменений связей между моделями и массовых импортов используйте полную
команду: одна изменённая категория или салон может влиять на видимость многих
услуг.

Автоматическое обновление выключено по умолчанию. Если в окружении уже работают
Celery worker и beat из этого проекта, задайте `MANTICORE_AUTO_INDEX=1`: beat
будет запускать полную синхронизацию раз в час. Сначала выполните ручную
загрузку и проверьте результаты поиска. Без Celery можно вызывать команду по
расписанию сервера с тем же окружением, что у Django. Не допускайте наложения
полных запусков (например, используйте `flock` для cron). Manticore, Celery
и серверный планировщик в этом изменении не устанавливаются.

Проверка после запуска: `GET /api/v1/search?query=стрижка` возвращает данные
и `pagination.totalCount`; ссылки в `data[].url` ведут только на внутренние
маршруты сайта. Страница интерфейса: `/search?query=стрижка`.
